Panduan untuk Claude Code saat bekerja di repositori ini. Lihat juga **`MEMORY.md`** (peta kode dari knowledge graph) untuk orientasi cepat modul & alur.

## Apa ini

**KidzPlayful** — web app kelas bermain digital anak 0–4 tahun: game sensorik/motorik, kelas bermain, Pojok Video, komunitas ortu, **event offline berbayar + pendaftaran**, **toko/Store** (mainan & bahan activity), **Catatan Perkembangan Bermain** (penilaian guru rubrik PAUD), dan **reminder WhatsApp**.

- **Stack:** Next.js 16 (App Router, TypeScript) + Supabase (Postgres + Auth + Storage). Tidak ada server terpisah — "backend" = Server Components (baca) + Server Actions (tulis) + **RLS** di Supabase.
- **Live:** `https://kidzplayful-fe2a.vercel.app` · **Repo:** `github.com/khabibrizal/kidzplayful` (public, deploy Vercel auto tiap push ke `master`).
- **Bahasa:** semua UI, komentar, teks, dan pesan commit ditulis dalam **Bahasa Indonesia** — ikuti gaya ini.

## Perintah

```bash
npm run dev      # dev server http://localhost:3000
npm run build    # build produksi (juga menjalankan ESLint; error = gagal)
npm test         # unit test (Vitest) — lib/domain & lib/game
npm run e2e      # end-to-end (Playwright)
npm run lint     # ESLint
node tools/<nama>.mjs   # skrip verifikasi e2e di PRODUKSI (puppeteer)
```

Sebelum commit: pastikan `npx tsc --noEmit` bersih dan `npm run build` sukses.
CI (`.github/workflows/ci.yml`) menjalankan `tsc --noEmit` → `npm test` (vitest) → `npm run build` di tiap PR & push ke `master` — jaga ketiganya tetap hijau.

## Variabel lingkungan (`.env.local`, gitignored)

- `NEXT_PUBLIC_SUPABASE_URL` — URL proyek Supabase
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` — kunci **publishable** (aman di browser; keamanan dijaga RLS)

Jangan pakai *secret key*. `NEXT_PUBLIC_*` harus ada **sebelum build** (juga di env Vercel).

## Arsitektur & pola (WAJIB diikuti)

- **Baca data** → fungsi di `src/lib/data/*.ts` dipanggil dari **Server Component**.
- **Tulis data** → **Server Action** (`'use server'`) di `src/lib/data/*-actions.ts`, dipanggil dari Client Component.
- **Client Component** (`'use client'`) hanya untuk interaktif (form, tombol, game, carousel).
- **Keamanan = RLS per tabel** + guard kode: `getAnakTerjamin` (login + kepemilikan anak; **sengaja TANPA gerbang langganan** — lihat aturan redirect di bawah), `getAdminTerjamin`, `getGuruTerjamin`, `adminDb()`/`db()`. Query "milik sendiri" **selalu** difilter `.eq('id'|'ortu_id', user.id)` (jangan `.single()` tanpa filter — admin bisa baca banyak baris → error).
- **Peran:** `profiles.is_admin` & `is_guru` + fungsi SQL `is_admin()`/`is_guru()`. Trigger `cegah_self_admin` mencegah user mempromosikan diri (hanya admin/SQL yang boleh ubah role). Peran hanya diberikan lewat SQL Editor atau halaman admin (Kelola Guru).
- **Uang/total dihitung ulang di server** (anti manipulasi); harga di-*snapshot* saat checkout/pendaftaran (`item_pesanan`, `pendaftaran_event.total`). Stok berkurang saat admin verifikasi.
- `params`/`searchParams` = Promise (harus `await`). Setelah menulis, panggil `revalidatePath('/...')`.
- **Form + Server Action — field harus ikut ter-reset.** React 19 mereset `<form action={serverAction}>` otomatis setelah action selesai, **tapi hanya field UNCONTROLLED**. Komponen client yang menyimpan nilai di `useState` tetap terisi setelah simpan — pernah menyebabkan bug nyata: nominal tak ter-reset DAN **URL foto nota transaksi sebelumnya ikut ter-submit** pada entri berikutnya. Aturan: nilai yang ter-submit dibuat **uncontrolled** (`defaultValue`, set lewat `ref` bila perlu); state khusus tampilan dibersihkan lewat **`usePadaResetForm`** (`lib/form-reset.ts`). Contoh: `InputRupiah`, `UploadNota`, `BudgetKategoriSelect`.
- **Kartu berbagi (canvas, tanpa dependency):** `lib/kartu-bersama.ts` (palet, pembungkus teks, pemuat aset, ornamen, tipe `IsiKartu`) dipakai oleh `lib/story-card.ts` (**1080x1920**, IG Story) dan `lib/feed-card.ts` (**1080x1080**, IG Feed). Isinya berasal dari SATU sumber - `ShareButton.isiKartu()` - jadi kedua kartu mustahil berbeda isi.
  - **Aturan "tidak boleh terpotong"** (keduanya dari keluhan nyata): teks memakai **`ukuranPas()`** yang mengecilkan font sampai benar-benar muat (cek jumlah baris **dan** lebar tiap baris) - jangan memotong dengan elipsis; foto memakai **`gambarMuat()` (`contain`)** di kartu Feed, karena sampul artikel sering memuat TULISAN sehingga `cover` memenggal kata.
  - **Perubahan tata letak WAJIB diperiksa visual** - output canvas tidak bisa dinilai dari membaca kode. Render lewat UI sungguhan dengan Playwright: buka `/artikel/<slug>`, klik Bagikan, pilih item menu, tangkap event `download`. Uji minimal dua kasus ekstrem: **artikel berjudul terpanjang** dan **artikel tanpa sampul**.
- **`redirect()` WAJIB membawa alasan yang terbaca pengguna.** Pantulan diam ke halaman asal **tidak bisa dibedakan dari tombol rusak**. Bug nyata: `getAnakTerjamin` dulu me-redirect ke `/pilih-anak` begitu langganan ortu kadaluarsa — mengetuk kartu anak seolah tak berfungsi. Selain itu gerbang itu menyalakan diri karena sebab yang bukan kedaluwarsa (baris `langganan` hilang/ganda → `.single()` gagal → status dipaksa `kadaluarsa`). Aturan sekarang: batasi akses lewat **kunci per konten** (`dibatasiTrial` → `boleh_trial` → 🔒 `Terkunci`), bukan pantulan; bila memang harus memantulkan, bawa alasannya di query string dan **tampilkan** di halaman tujuan (`/pilih-anak?galat=…`).
- **Pencarian pada daftar yang dipaginasi harus SERVER-side.** Menyaring di klien hanya mencari di halaman yang sedang terbuka, dan itu terbaca sebagai "datanya tidak ada". Bila kata kunci ikut ke filter PostgREST `or=(...)`, **bersihkan dulu** `% _ , ( ) " * \` — koma & kurung memecah bentuk klausa, `%`/`_` adalah wildcard ILIKE. Syarat pada tabel induk tak bisa di-OR-kan dengan syarat pada tabel anak dalam satu query: kumpulkan id dari tabel anak lebih dulu, lalu gabungkan sebagai `id.in.(…)` (contoh: `/admin/langganan`).
- **Penamaan tampilan ≠ kunci.** Label menu "Kelas Bermain" sudah diganti jadi **"Ide Bermain"**, TAPI hanya labelnya. `key: 'kelas-bermain'` di `MENU_ADMIN`, rute `/admin/kelas-bermain` · `/kelas-saya` · `/kelas/[id]`, dan tabel `kelas_bermain` **tetap** — key itu tersimpan di konfigurasi Akses Menu di database, menggantinya mencabut hak akses semua role. "Event Kelas Bermain" adalah fitur BERBEDA dan tidak ikut diganti; judul SEO/landing juga tidak.
- **Hak akses langganan = DATA, bukan cabang `if`.** Paket ada di tabel `paket_langganan` (0089) dan **status langganan menempel pada ANAK** (`langganan_anak`), bukan akun — satu akun boleh punya anak Preschool dan anak Basic. Semua keputusan akses lewat **`lib/domain/entitlement.ts`** (`hakAksesAnak` / `hakAksesAkun`), jangan menambah cabang `status === 'aktif'` baru. Fitur yang tak punya konteks anak (diskon event/produk, Komunitas, detail materi) memakai **paket TERTINGGI** di akun (`urutan` terbesar) dan aturan itu **wajib ditulis di UI**. Fasilitas berbayar (mis. worksheet) default-nya **terkunci**: prop seperti `bolehWorksheet` berbawaan `false` supaya lupa memasang penjaga tidak berarti bocor.
- **Batas hari langganan: satu aturan, WIB, dan hari terakhir IKUT.** `aktif_sampai` adalah tanggal (`date`), bukan momen — jangan bandingkan `new Date()` dengan `aktif_sampai + 'T00:00:00Z'`: sejak jam 07:00 WIB hari itu sudah "lewat", jadi hari yang sudah dibayar hilang. Bandingkan **string tanggal WIB** (`tanggalWIB(sekarang) <= aktif_sampai`) di TypeScript dan `public.hari_ini_wib()` (0094) di SQL — `current_date` di Supabase adalah tanggal **UTC**, yang antara 00:00–07:00 WIB masih kemarin. Dua sisi yang memakai batas berbeda pernah menghasilkan bug nyata: halaman menyebut langganan anak sudah berhenti, sementara RPC booking masih menganggapnya member dan memberi konsultasi gratis.
- **Mencabut hak ≠ mengakhiri periode hari ini.** `hentikanPaketAnak` dulu menyetel `aktif_sampai = hari ini` dan membiarkan `paket_id`; hasilnya anak itu tetap aktif seharian lalu masih dapat **3 hari tenggang berhak penuh** — tombol "Hentikan" terbaca rusak. Penghentian sekarang mengakhiri periode **kemarin (WIB)** DAN **mengosongkan `paket_id`**, karena masa tenggang adalah kemurahan untuk yang lupa memperpanjang, bukan untuk yang dihentikan. Aturan umumnya: kalau sebuah aksi seharusnya mencabut akses, ujilah lewat **matriks hak akses** (`domain/entitlement.ts`), bukan dengan melihat tanggalnya berubah.
- **Server action yang melaporkan sukses harus tahu ada yang berubah.** `.update().eq(...)` yang tak mencocokkan satu baris pun **bukan error** di PostgREST — ia mengembalikan 0 baris dan aksi lama tetap menjawab `{ ok: true }`. Tambahkan `.select('<kolom kunci>')` lalu periksa panjangnya, dan kembalikan pesan yang menyebut apa yang tak ditemukan.
- **Menutup fungsi SQL butuh DUA pencabutan, dan wajib dibuktikan.** Ada dua pemberi izin: **`PUBLIC`** (bawaan Postgres — setiap fungsi baru bisa dieksekusi siapa pun) dan peran **`anon`/`authenticated`** (default privileges Supabase pada skema `public`). Mencabut salah satu saja tidak menutup apa pun: `hari_ini_wib()` baru benar-benar tertutup setelah 0094 (`from public`) **dan** 0095 (`from anon`), sedangkan `konsultasi_memakai_slot` di 0096 hanya dicabut dari `anon` dan **tetap bisa dipanggil kunci anon** (`HTTP 200`) sampai 0097. Resepnya: `revoke execute on function … from public;` **dan** `… from anon;`, lalu **buktikan dengan benar-benar memanggil `/rest/v1/rpc/<nama>` memakai kunci anon** — jawaban yang benar `42501`, bukan `200`. Jangan percaya baris `revoke` yang tak diuji.
- **Kapasitas berbayar (slot/kuota) baru terpakai SESUDAH dibayar.** Booking konsultasi yang belum dibayar hanya **draft** berbatas waktu: ia tak dihitung `sisa_kuota_konsultasi` dan tak muncul di antrean psikolog (0096). Yang bertotal 0 — kuota gratis paket atau diskon member 100% — memakai slot sejak awal, karena memang tak ada yang perlu dibayar. Konsekuensinya **beberapa orang tua bisa berebut satu tanggal dan yang lebih dulu membayar yang dapat**, jadi kuota WAJIB diperiksa ulang **tepat saat baris mulai memakai slot** — lewat **trigger** (`cek_slot_konsultasi`), bukan hanya di server action; kalau tidak, `PATCH` REST langsung tetap bisa menyerobot. Aturan ini punya kembaran murni untuk label di `domain/konsultasi-slot.ts` (`aman`/`draft`/`hangus`) — **penegaknya tetap SQL**, ubah keduanya bersama.
- **Kuota: cakupan & arti angka 0 berbeda per fitur — tulis keduanya di layar.** Kuota **konsultasi gratis milik ANAK** (paket anak itu), kuota **unduh worksheet milik AKUN** (dihitung per `ortu_id`, haknya dari paket TERTINGGI) — satu kolam untuk semua anak, jadi kalau ditaruh di kartu anak wajib diberi keterangan "kuota akun, dipakai bersama". Dan angka 0 tidak berarti sama: `worksheet_kuota_jumlah = 0` = **tanpa batas**, sedangkan `konsultasi_gratis_jumlah = 0` = **tidak ada kuota gratis**. Pembacanya satu untuk semua halaman (`lib/data/kuota-anak.ts`) — jangan menghitung ulang kuota di halaman, dua salinan aturan = dua angka berbeda.
- **Kohort kurikulum milik ANAK, bukan akun.** Tema yang terbuka untuk kakak bisa masih terkunci untuk adik (`langganan_anak.bulan_kurikulum`, 0098). `statusTema()` di `domain/kurikulum.ts` **hanya menerima `bulanAnak`** — jangan membuat varian tingkat akun, sebab itulah jalan pintas yang diam-diam menggabungkan kohort. Halaman kurikulum wajib menyebut **nama anak** yang sedang dibuka dan menampilkan pemilih anak; tema terkunci wajib menyebut **sebabnya** ("terbuka saat langganan Bima masuk bulan ke-4"), kalau tidak perbedaan kakak-adik terbaca sebagai kerusakan. Tema tanpa `bulan_kurikulum` dianggap **terbuka** — default yang salah arah akan mengunci konten yang tadinya jalan.
- **Penanda "gratis/terbuka" membebaskan KUOTA, bukan KEANGGOTAAN — dan urutan gerbangnya menentukan itu.** `mintaWorksheet` dulu memeriksa `worksheet_terbuka` PALING AWAL lalu mengembalikan URL, sehingga siapa pun yang login bisa mengunduh meski bukan pelanggan. Periksa **hak akun lebih dulu**, penanda bebas-kuota sesudahnya. Dan hak yang berasal dari **TRIAL bukan hak berbayar**: paket trial bisa membawa `kuota = 0` yang berarti *tanpa batas*, jadi pemeriksa hak wajib tahu `status`-nya (`hakAksesAkun().status`), bukan hanya "ada paket".
- **Plafon seumur-hidup dihitung dari SELURUH riwayat, bukan periode berjalan.** Batas "1× selama trial" yang dihitung per bulan memberi jatah dua kali kepada trial yang menyeberang bulan. Dan plafon semacam itu hanya boleh MENGURANGI hak paketnya, tak pernah menambah — kalau tidak, ia menghidupkan fitur yang sengaja dimatikan admin.
- **Cadangan "tabel belum ada" biasanya MEMBUKA, tapi untuk plafon anti-penyalahgunaan ia harus MENUTUP.** Kalau `unduhan_worksheet` tak terbaca, "satu kali" tak bisa ditegakkan sama sekali; jatah gratis tanpa batas lebih merugikan daripada tombol yang mati. Pilih arah cadangan menurut apa yang rusak bila salah, bukan menurut kebiasaan.
- **Jangan embed PostgREST ke tabel yang punya DUA foreign key ke sana.** `pendaftaran_konsultasi` menunjuk `profiles` dua kali (ortu & psikolog); `ortu:ortu_id(...)` berisiko PGRST201 dan kegagalannya mematikan SELURUH daftar, bukan satu kolom. Ambil profilnya lewat query terpisah lalu petakan di kode.
- **Cadangan pra-migrasi tidak boleh GAGAL KE ARAH TERBUKA.** Menyimpan materi EVENT tanpa kolom `jenis` sempat "diselamatkan" dengan membuang kolomnya — hasilnya baris ber-kategori tanpa posisi, dan `bulan < 1` berarti *terbuka*, sehingga materi yang ditandai "bukan untuk pengguna" justru paling mudah dilihat. Tanyakan **apa yang bocor bila salah**, bukan hanya "apa yang rusak bila gagal": untuk hal yang menyembunyikan konten, **tolak menyimpan dengan pesan yang menyebut migrasinya**.
- **Penyaring yang menentukan APA YANG TERLIHAT PENGGUNA dipasang di QUERY sumbernya, bukan di tiap pemanggil.** `getKelasAktifCached` dipakai 7 tempat; menyaring `jenis = 'event'` di masing-masing berarti satu pemanggil yang lupa sudah cukup untuk membocorkannya ke halaman anak. Dan nilai yang membuat sebuah baris "tak berlaku" (mis. posisi kurikulum untuk materi event) **dinolkan di server**, bukan sekadar disembunyikan field-nya — form yang tak menampilkan sebuah field tetap bisa mengirim nilainya.
- **Kuota yang dibagi ke beberapa kelompok dibatasi pada TOTALnya, bukan per kelompok.** `min(dijalani[b], siklus)` memberi batas penuh kepada SETIAP kategori usia, sehingga 3 bulan berbayar membuka sampai 5 bundel bulanan begitu anak berganti kategori. Bagikan kuotanya menurut urutan waktu dan hentikan saat totalnya habis. Dan periode yang **tak memberi apa pun** (mis. usia anak di celah antar-kategori) tidak boleh menghabiskan kuota — kalau tidak, orang membayar lalu tetap tak menerima apa-apa.
- **Kalender dan hak bayar adalah DUA batas, dan kadensa butuh keduanya.** Bulan kurikulum seorang anak = `min(bulan kalender sejak mulai, bulan yang sudah dibayar)` (`domain/siklus-kurikulum.ts`, 0104). Memakai hanya jumlah bulan dibayar membuat pelanggan tahunan membuka 12 bulan materi di hari pembayaran; memakai hanya kalender membuat anak yang berhenti berlangganan terus naik. Penghitung "sudah dibayar berapa bulan" (`bulan_kurikulum`) bukan nomor bulan yang tampil — jangan pakai ia langsung untuk menggerbangi konten.
- **Kalau sebuah aksi membuka panel di luar layar, BAWA penggunanya ke sana.** Form yang dirender di atas daftar sementara tombolnya di bawah membuat tombol itu terasa rusak. Gulirkan (`scrollIntoView`) lewat efek yang bergantung pada **penghitung pembukaan**, bukan pada state form-nya — kalau tidak, halaman akan menggulir setiap kali pengguna mengetik. Dan sebutkan **identitas baris** di kepala form, supaya jelas yang terbuka memang baris yang ditekan.
- **"Punya paket" BUKAN sinonim "berhak".** Trial, tenggang, dan berbayar semuanya punya `paketTertinggi` — yang membedakan adalah `status`. Gerbang `!paketTertinggi && boleh_trial === false` karena itu tak pernah menutup apa pun untuk anak TRIAL. Pakai `bolehBukaTema()` (`domain/entitlement.ts`), dan nilai per ANAK bila halamannya punya konteks anak: satu akun bisa punya anak berbayar dan anak trial sekaligus.
- **Satu flag pembatas tidak boleh dipakai untuk beberapa fitur.** `batasi = !status.game` sempat dipakai mengunci game, video, DAN Ide Bermain — sehingga paket yang memberi game tapi bukan Ide Bermain mengunci fitur yang salah. Namai per fitur.
- **Nilai TURUNAN diturunkan oleh SERVER saat menyimpan, jangan dipercayakan ke kiriman klien.** `kelas_bermain.usia_min/max` adalah snapshot dari kategori usianya; karena form mengirim balik snapshot LAMA yang dimuatnya saat dibuka, mengubah master lalu menekan Simpan tak mengubah apa pun — tanpa galat sama sekali. Server kini menurunkannya ulang dari master (`denganRentangKategori`). Dan bila master berubah, penjalarannya dilakukan di action master itu, dengan **jumlah baris yang ikut berubah dilaporkan** ke layar — perubahan yang menjalar diam-diam sama membingungkannya dengan yang tak menjalar.
- **Gerbang dengan lebih dari satu sebab wajib MENGEMBALIKAN sebabnya, bukan boolean.** Tema kurikulum bisa terkunci karena **bulan** (menunggu akan membukanya) atau karena **usia** (menunggu TIDAK akan membukanya); keduanya sempat memakai satu pesan "menunggu bulan berikutnya", sehingga anak di bulan ke-1 melihat "terbuka bulan ke-1" dan orang tua menunggu sesuatu yang tak akan datang. Pakai `kunciKarena()`, dan tulis kalimat yang berbeda untuk sebab yang berbeda — pesan yang salah sebab lebih merugikan daripada tak ada pesan.
- **Pembekuan menahan nilai SELAMA periode berjalan, bukan memakukannya di masa lalu.** `mulaiSiklus` sempat diturunkan dari `siklus` (yang ditahan bayaran), sehingga anak dengan bayaran tertahan dibekukan pada umurnya SETAHUN LALU — ia jatuh ke luar semua kategori usia dan seluruh temanya terkunci. Pisahkan **penomoran** (ditahan hak/bayaran) dari **jangkar waktu** (selalu periode yang sedang dijalani, `kalenderKe`).
- **Kalau sebuah pengelompokan bergantung pada usia, BEKUKAN acuannya.** Umur yang dihitung ulang setiap render berarti ulang tahun di tengah periode mengganti isi periode itu — checklist yang sedang dikerjakan lenyap dari daftar. Hitung umur pada **awal periode** (`konteksKurikulum` → `umurBeku`), dan turunkan periodenya dari satu tanggal tersimpan, bukan dari penghitung yang dinaikkan berkala: penghitung tersimpan meleset begitu ada koreksi manual, refund, atau backfill, dan melesetnya tak terlihat sampai orang tua mengeluh.
- **Cadangan pra-migrasi tidak boleh "netral" kalau netral berarti MENGUNCI.** Saat kolom baru belum ada, pilih nilai yang mempertahankan perilaku LAMA, bukan nilai terkecil. `siklusBerjalan` tanpa `kurikulum_mulai` memakai jumlah bulan dibayar (perilaku lama); memilih siklus 1 akan mengunci tema yang tadinya terbuka, dan konten yang mendadak terkunci terbaca sebagai fitur dicabut.
- **Indeks unik BARU hampir selalu bertabrakan dengan nilai bawaan lama — rapikan datanya di migrasi yang sama.** `create unique index` pada `(bulan_kurikulum, urutan)` gagal seketika (`Key (…)=(1, 0) is duplicated`) karena seluruh materi lama memakai default `(1, 0)`. Kegagalannya aman (tak ada yang berubah setengah jalan), tapi migrasinya jadi tak bisa dijalankan siapa pun. Pola yang benar: **`row_number()` menomori ulang lebih dulu**, baru indeksnya dibuat — dan urutkan penomorannya dengan pemutus deterministik (`…, created_at, id`) supaya dijalankan ulang hasilnya sama.
- **Keunikan kurikulum dihitung PER KATEGORI USIA, bukan global.** Bayi dan Prasekolah adalah kurikulum berbeda dan berhak sama-sama punya Bulan 1 Minggu 1; indeks global (0102) membuat keduanya saling merebut slot, dikoreksi 0103 (`kelas_kurikulum_posisi_kategori`). Kolom pengelompok yang **nullable** wajib dibungkus `coalesce(kategori_usia_id, uuid nol)` — tanpa itu tiap `NULL` dianggap unik dan aturannya bocor persis untuk baris yang paling mungkin salah. `urutan` **= minggu 1..4**; batasnya ditegakkan di **server action**, bukan hanya di form.
- **Prop identitas/hak yang opsional akan lupa dipasang.** `KelasIsi` menerima `anakId?`, dan Mode Anak merendernya tanpa itu — checklist mati & tombol game hilang di tempat yang justru paling sering dipakai. Saat menambah prop semacam ini, sisir **semua** pemanggilnya (`grep -n "<NamaKomponen" src`), bukan hanya berkas yang sedang dikerjakan.
- **Styling:** kelas global `kp-*` (tombol jelly, kartu, chip) di `globals.css` + CSS Modules `*.module.css`. Palet pastel lavender/mint/peach, tinta `#5b5170`. Maskot `Pewi`, logo `public/logo.png` (komponen `Logo`).

## Database & migrasi

- Migrasi SQL di `supabase/migrations/0001..0099`, **dijalankan MANUAL berurutan** di **Supabase SQL Editor** (tidak ada CLI migrate). Saat menambah skema: buat file `00NN_*.sql` baru, lalu minta user menjalankannya.
- **WAJIB — kolom baru harus TOLERAN sampai migrasinya dijalankan.** Karena kode ter-deploy lebih dulu daripada migrasi manual, JANGAN memasukkan kolom baru ke `select`/`insert` di alur kritis (daftar/katalog, pendaftaran, simpan data). Query akan gagal `42703` dan mematikan fitur yang tadinya jalan. Pola yang benar (contoh: `lib/data/kuota-event.ts`): baca kolom baru lewat **query terpisah** yang mengembalikan nilai default bila gagal, dan pada write **retry tanpa kolom baru** bila error kolom-hilang. Fitur baru menyala otomatis setelah migrasi dijalankan.
- Tabel utama: `profiles`, `anak`, `langganan`, `tema`, `paket_aset` (`butir` jsonb = isi game), `hasil_main`, `video`, `kelas_bermain` (`bahan`/`aktivitas` jsonb), `favorit`, `riwayat_kelas`, `event`, `pendaftaran_event`, `produk`, `keranjang_item`, `pesanan`, `item_pesanan`, `catatan_perkembangan`, `jadwal_psikolog` (jadwal & durasi, diisi psikolog), `psikolog_profil` (master profil, diisi admin).
- **Storage** bucket `aset` (publik baca): tulis admin (folder `produk/`, `event/`, `worksheet/`), user hanya folder `bukti/` (bukti bayar).

## Konvensi menambah fitur

1. Data: tambah reader di `lib/data/<fitur>.ts` + action di `<fitur>-actions.ts` (`'use server'`).
2. Tipe di `src/lib/game/tipe.ts`; util format di `src/lib/format.ts`.
3. Halaman di `src/app/<rute>/page.tsx` (Server) + komponen Client bila perlu; admin di `src/app/admin/<fitur>/` + tambah link di `src/app/admin/page.tsx`.
4. Skema baru → migrasi `00NN_*.sql` + RLS (baca milik sendiri/admin/guru sesuai kebutuhan).
   - **Mesin game baru** WAJIB migrasi perluas CHECK `paket_aset_mesin_check` (pola `0025..0037`, `0074`) — tanpa itu INSERT paket ditolak DB (error ter-redact di production).
5. Verifikasi: `tsc --noEmit` + `npm run build`; untuk fitur besar buat skrip `tools/<fitur>_check.mjs` (puppeteer) yang uji e2e di produksi lalu **bersihkan data uji**.
6. Commit (Indonesian) + push → Vercel auto-deploy. Ingatkan user menjalankan migrasi bila ada.

## Catatan lingkungan

- Shell user = **PowerShell**: `&&` TIDAK berlaku — pakai `;` atau baris terpisah.
- **Git Bash mengonversi argumen berawalan `/`** menjadi path Windows (`/artikel/x` menjadi `C:/Program Files/Git/artikel/x`). Saat mengoper path URL ke skrip Node, awali perintah dengan `MSYS_NO_PATHCONV=1`.
- **Dev server yatim**: `next dev` bisa tertinggal memegang port 3000 setelah proses induknya mati. Instance baru menolak start (*"Another next dev server is already running"*) dan halaman balas **500** dari proses lama yang rusak — mudah disalahartikan sebagai bug kode. Matikan PID yang disebut di pesan Next.js (`taskkill //PID <pid> //F`), lalu jalankan ulang. Jangan menjalankan `npm run dev` bersamaan dengan `npm run build` — keduanya menulis ke `.next`.
- Commit tanpa gpg sign bila perlu: `git -c commit.gpgsign=false commit ...`.
- Deploy Vercel **Hobby** butuh repo **public**. **Kegagalannya SENYAP**: kalau repo diprivatkan, deploy diblokir tapi `git push` tetap sukses dan CI tetap hijau — fitur baru sekadar tidak pernah muncul (pernah 5 hari, Agustus 2026). Setelah repo dipublikkan lagi, Vercel **tidak** otomatis membangun commit yang masuk saat privat → picu dengan `git commit --allow-empty` atau Redeploy. Diagnosis: `docs/RUNBOOK-OPERASIONAL.md` **RB-10**. Reset password butuh **SMTP** + **Redirect URL** `/reset-sandi` diatur di Supabase Auth.
- Akun admin uji: `admin@kidzplayful.app`. Peran guru diaktifkan via Admin → Kelola Guru (guru daftar dulu).
